# 0.4.1 — Fix OMP conversation black screens

OMP's phased `todo` tool can return `op/list` input and `details.phases` output. The previous renderer assumed a flat `todos` list and called `.filter()` on `null`, unmounting the chat area. This was reproduced with an affected transcript; the OMP backend could continue running while its conversation appeared blank. The defect exists in 0.3.3-beta.2 and 0.4.0.

This patch:

- Normalizes phased OMP tasks and reads their current status from returned task state, including result-only updates and cleared lists.
- Displays unknown, partial or truncated todo payloads as structured data instead of crashing.
- Isolates rendering failures to the individual tool card, with a raw-data fallback that preserves the conversation, composer and stop control.
- Adds parser, running-conversation and error-boundary regressions, plus an installed-package regression that opens persisted OMP phased/unknown todo history through the shipped client.

Install `dsh-remote-agents@0.4.1` in the plugin manager of your active DSH profile. Finish running tasks before restarting the desktop app to load the updated host and interface. Existing conversation history does not need to be deleted or migrated. Runtime compatibility is unchanged from 0.4.0.
