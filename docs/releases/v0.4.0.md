# 0.4.0 — Stable workspace and conversation management

DSH Remote Agents 0.4.0 moves unified local/SSH conversations to the stable npm `latest` channel. It supports DSH **0.2.2-rc.1**, Node.js **22+**, Claude Code **≥2.1.318 and <3**, Codex **0.167.x**, and OMP **≥18.17 and <19**.

## Reliability

- Retry workspace discovery with bounded backoff, preserve known hosts during outages, and refresh on reconnect/foreground. Detect a host/interface version mismatch and request a desktop restart.
- Save partial settings with a revision precondition, retain existing choices, reject stale saves, and show saved/effective values.
- Keep active conversations responsive while reducing idle and background polling; prevent overlapping requests.
- Present recovery guidance for quota, sign-in, incompatible versions, missing CLIs and connection failures. Prompt retries always remain explicit.

## Remote updates

Updates now inspect the installed executable and show a fixed, tested target plus the exact command. Recognized npm, pnpm, Bun and Claude native installations can update through their own installation method. Unknown/standalone installations receive manual instructions. The server rejects stale update plans and verifies the resulting executable version. Compatible installations are not downgraded. No remote software is updated by discovery or refresh.

## Management

External sessions can be renamed, pinned, archived/restored, searched by retained message text, and exported to Markdown or JSON. Workspace registrations can be removed while preserving files and conversation history. The new-session control remains visible without hovering.

## Validation and scope

The suite covers protocol framing, settings conflicts, stale polls, connection recovery, approvals, interruption/resume, archive/search/export and source-aware pinned updates. `npm run test:package` installs the actual tarball into an isolated directory and exercises its host routes, shipped client factory and a real deterministic app-server subprocess. UI primitives and model replies in this test are fixtures; they do not stand in for a successful live provider request. `npm run test:smoke` runs a real isolated tmux lifecycle. CI covers Linux/macOS and Node.js 22/24.

Attachments, rich interactive questions, native message-body search and cross-engine migration remain outside this release's supported scope. Provider accounts must have usable authentication and quota. Remote updates are validated with controlled test commands, not by changing existing servers during release verification.

## Upgrade

Install `dsh-remote-agents@0.4.0` (or `@latest`) in the plugin manager of the **running DSH profile**, then restart the desktop app. Existing transcripts and workspace registrations are retained. Do not install into an unrelated `web` profile when using the desktop app.
